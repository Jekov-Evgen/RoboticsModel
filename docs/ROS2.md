# Мост ROS 2

`robotics_model.ros2` запускает сцену Robotics Model как узел ROS 2: публикует состояние суставов, позы тел (`/tf`), датчики и время симуляции, принимает команды суставов и скорости.

> **Статус честно.** Логика моста (конверсия осей, имена суставов, команды, управление временем, сообщения датчиков) покрыта обычными тестами. Сам узел `rclpy` проверен только против **заглушек** `rclpy` и сообщений с тем же составом полей (`python/tests/fake_ros.py`): ROS 2 на машине разработки не установлен, поэтому **на живом ROS 2 узел не запускался**. Заглушки ловят ошибки логики, но не ошибки использования настоящего API; при первом запуске возможны мелкие правки. Если запустите — сообщите, что получилось.

## Запуск

Нужны ROS 2 (Humble, Jazzy и т. п.) и пакет `robotics-model` в том же окружении Python:

```sh
source /opt/ros/<distro>/setup.bash
python3 -m venv --system-site-packages .venv && . .venv/bin/activate   # видны пакеты ROS
pip install .
python -m robotics_model.ros2 --ros-args -p scene:=examples/manipulator_3dof.robot
```

Параметры узла:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `scene` | `""` | файл `.robot` (если пусто и нет `urdf` — встроенный манипулятор) |
| `urdf`, `fix_base` | `""`, `false` | загрузить URDF; `fix_base` закрепляет основание манипулятора |
| `real_time_factor` | `1.0` | во сколько раз симуляция быстрее реального времени |
| `step_rate`, `publish_rate` | `200`, `50` Гц | частоты таймера шага и публикации (по настенному времени) |
| `ros_frame` | `true` | переводить оси из Y-вверх в Z-вверх (REP 103); `false` — оси движка как есть |
| `wheel_radius`, `track_width`, `turn_scale` | `0`, `0`, `1.0` | колёсная база для `/cmd_vel`; `0` = оценить по сцене |

## Темы и сервисы

| Имя | Тип | Направление |
|---|---|---|
| `/clock` | `rosgraph_msgs/Clock` | публикуется: время симуляции (`use_sim_time:=true` у остальных узлов) |
| `/joint_states` | `sensor_msgs/JointState` | публикуется: приводные суставы (Hinge, Slider), положение, скорость, усилие |
| `/tf` | `tf2_msgs/TFMessage` | публикуется: поза каждого тела относительно `world` |
| `/<датчик>/data` | `sensor_msgs/Imu` | IMU: ускорение, угловая скорость, ориентация |
| `/<датчик>/scan` | `sensor_msgs/LaserScan` | 2D-лидар |
| `/joint_commands` | `sensor_msgs/JointState` | принимается: уставки положения по именам (`position`) |
| `/cmd_vel` | `geometry_msgs/Twist` | принимается: скорость колёсного робота |
| `/reset` | `std_srvs/Empty` | сервис: вернуть сцену в начальное состояние |
| `/pause` | `std_srvs/SetBool` | сервис: пауза / продолжить |

Датчик публикуется один раз на каждый его отсчёт; `<датчик>` — имя датчика в сцене.

## Соглашения

- **Имена суставов** — по дочернему телу (в движке у суставов нет имён): сустав, в конце которого `forearm`, называется `forearm`. Имена должны быть уникальны.
- **Оси.** Движок — Y вверх, ROS — Z вверх: `(x, y, z) → (x, −z, y)`, ориентации преобразуются так же. Импортированные из URDF роботы возвращаются в исходные оси URDF. Угол сустава от выбора осей не зависит.
- **Команды суставов** работают, если у сустава включён регулятор положения (PID у суставов манипулятора из примера). Скоростной мотор командой положения не управляется.
- **`/cmd_vel`** работает без обратной связи: скорости колёс считаются по идеальной кинематике. У skid-steer ровера реальный поворот слабее идеального (в `examples` и демо ≈ 0,57 от расчётного) — подберите `turn_scale`.
- **Время** — симуляционное: `/clock` и метки заголовков берутся из `World.time`.

## Чего нет

- Камер (`sensor_msgs/Image`): их рисует только редактор.
- Датчиков силы/момента, энкодеров отдельными темами (положения суставов уже идут в `/joint_states`).
- Действий и контроллеров `ros2_control` (`FollowJointTrajectory`); траектории можно исполнять через `rm.follow_trajectory` внутри Python.
- URDF в RViz: узел публикует позы тел, а не описание робота (`robot_description`).
