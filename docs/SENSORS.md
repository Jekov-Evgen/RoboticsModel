# Датчики

Регуляторы раньше видели точный угол и скорость. Модуль датчиков добавляет реалистичные измерения: шум, смещение, дрейф, квантование, частоту опроса, задержку и пропуски. Через них же можно замкнуть ПИД-регулятор и увидеть, как ухудшается управление.

## Где живут датчики

- `include/robotics/sensors/sensor.hpp` — данные: `SensorType`, `NoiseModel`, `Sensor` (конфигурация + `SensorState`). Датчики хранятся в `World::sensors`, поэтому копии World (Undo, снимок для Reset, сохранение) переносят их вместе с телами; `World::removeBody` удаляет датчики тела и перенумеровывает остальные.
- `World::step()` датчики **не** читает. Их продвигает `updateSensors(world, dt)` после каждого шага; `stepSimulation(world, dt)` = `step` + `updateSensors`. Так делают редактор (цикл симуляции) и CLI.
- `src/sensors/sensors.cpp` — модели измерений, шум, такт, задержка; `src/sensors/raycast.cpp` — точные пересечения луча с формами.
- Камера: конфигурация в ядре, рендер — в редакторе (Metal). CLI изображения камеры не строит.

## Конвейер одного отсчёта

1. Отсчёт берётся, когда `world.time ≥ nextSampleTime` (частота `rate`, Гц; `0` — каждый шаг). Между отсчётами выход удерживается (sample-and-hold).
2. Идеальное значение `truth` по модели датчика.
3. Для каждого канала: `walk += biasWalk·√T·N(0,1)`; `v = truth + bias + walk + σ·N(0,1)`; округление до `resolution` (у энкодера ещё шаг `2π/counts` или `1/counts` м).
4. С вероятностью `dropout` отсчёт теряется — повторяется предыдущее измерение (`dropped` считает такие отсчёты).
5. Линия задержки на `latency` отсчётов: выход — измерение `latency` отсчётов назад; в начале повторяется первый отсчёт.

ГСЧ — `std::mt19937_64(seed)` (портируемый по стандарту) и собственный Бокс–Мюллер (`sampleNormal`), а не `std::normal_distribution`, результат которого зависит от стандартной библиотеки. Одинаковые seed и входы дают одинаковые показания.

## Модели

| Тип | Каналы | Модель |
|---|---|---|
| Encoder | position (рад / м) | `Joint::angle` соединения, у которого тело датчика — потомок (`Joint::b`); квантование по `encoderCounts` (на оборот или на метр) |
| Joint velocity | velocity | скорость координаты соединения |
| IMU | accel xyz, gyro xyz, quat wxyz | удельная сила `a − g` в системе датчика (покой: +9,81 вверх; свободное падение: ≈0); `a` — конечная разность скорости точки крепления между шагами (на первом шаге — `ω×(ω×r)`); гироскоп — `ω` в системе датчика; ориентация — точный кватернион, повёрнутый на случайный вектор σ = `orientationNoise` |
| Force/torque | force xyz, torque xyz | усилие, которое родитель передаёт потомку через соединение, в якоре, в системе датчика: `−reactionImpulse/dt`, `−reactionAngularImpulse/dt`, плюс мотор, ограничения и усилие регулятора вдоль оси |
| Contact | in_contact, normal_force | касание любого контакта с телом; сумма `normalImpulse/dt` |
| Rangefinder | range | луч вдоль +X датчика |
| 2D lidar | range_0…range_N−1 | N лучей в плоскости X–Z, FOV `fov`, положительные углы — влево (к −Z) |
| Camera | — | RGB и глубина рендерятся редактором (`fov` — вертикальный угол, `width × height`) |

Система датчика: +X вперёд, +Y вверх, +Z вправо; поза крепления (`position`, `orientation`) — в системе тела. Лучи игнорируют тело, на котором стоит датчик. Нет отражения или отражение ближе `minRange` → показание `maxRange`. Луч, начинающийся внутри формы (или под полом), даёт попадание на расстоянии 0 (датчик закрыт). Шум группы `noise` относится к основному сигналу (энкодер, скорость, дальность, акселерометр, сила, сила контакта), `noise2` — к гироскопу и моменту.

## Обратная связь регулятора

`Sensor::feedsController` у энкодера (и датчика скорости) передаёт показание в `ControllerState::sensorFeedback / feedbackPosition / feedbackSpeed`; `applyControllers` использует их вместо идеальных значений на следующем шаге. Скорость для D-составляющей у энкодера — конечная разность его выхода, поэтому шум и квантование усиливаются в D (хорошо видно на графике). Телеметрия хранит и измерение (`measured`), и истинные `angle`/`speed`: в Control Lab на первом графике появляются кривые Measured и True. Удаление датчика возвращает идеальную обратную связь после следующего `updateSensors`.

В Control Lab: «Feedback: Ideal / Encoder sensor» и поля Noise σ, Latency (отсчёты), Counts, Rate. При выборе Encoder sensor отсутствующий энкодер создаётся автоматически.

## Камера (редактор)

`SceneView renderSensorCamera:` рендерит сцену из позы датчика в offscreen-текстуру без MSAA (отдельные pipeline с одним сэмплом) без гизмо. Глубина копируется из depth-буфера (`MTLBlitOptionDepthFromDepthStencil`): буфер reversed-Z с бесконечной дальней плоскостью, `d = near / z`, `near = 0,03`, поэтому метрическая глубина вдоль оптической оси `z = 0,03 / d`; пустые пиксели — `maxRange`. Изображение показывается в правом нижнем углу вьюпорта (RGB | глубина) и в окне Sensors. Во время симуляции кадр рендерится с частотой камеры.

## Редактор

- Инспектор → **Sensors**: «+ Add sensor» (IMU, Rangefinder, 2D Lidar, Camera, Contact; Encoder / Joint velocity / Force-torque — если у детали есть соединение с родителем), список датчиков детали, поля частоты, шума, задержки, дальностей, FOV, лучей, крепления, Remove. Все изменения отменяются ⌘Z.
- Вьюпорт: лучи лидара/дальномера (зелёные) и точки попадания (красные), пирамида камеры, оси IMU, маркер крепления.
- Simulation → **Sensors (Live Readings)… (⌘K)**: значения и truth всех каналов, график выбранного канала, вид скана лидара сверху, изображения камеры; **Record CSV…** пишет каждый отсчёт во время симуляции, **Export history…** сохраняет буфер графиков.
- Examples → **Sensor Rover** (лидар на голове, IMU на шасси, камера, энкодеры колёс, препятствия) и **Noisy PID** (испытательный стенд ПИД, регулятор читает энкодер: σ = 0,02 рад, 256 отсчётов/оборот, задержка 30 мс).

## CLI

```text
robotics_cli --sensor-rover-demo --seconds 5 --sensor-csv sensors.csv
robotics_cli --noisy-pid-demo --seconds 4 --control-csv pid.csv
```

CSV датчиков в длинном формате: `time,sensor,name,type,channel,value,truth` — по строке на канал каждого датчика, который сделал отсчёт на этом шаге.

## Ограничения

- Лучи учитывают только формы столкновений (box, sphere, cylinder) и пол; визуальные меши лучи не видят. Для новых форм (convex hull) `raycastBody` — единственное место, где нужно делегировать в общий raycast ядра; `switch` по `Shape` исчерпывающий, компилятор укажет его.
- Акселерометр по конечной разности чувствителен к рывкам контактов (как и настоящий).
- Датчик силы показывает средние за шаг импульсы решателя; при подшагах это среднее по шагу.
- Состояние датчиков не сохраняется в `.robot`; после загрузки или Reset генераторы начинают с seed.
- Камера рендерится только в редакторе macOS; история графика хранит первые 12 каналов датчика.
