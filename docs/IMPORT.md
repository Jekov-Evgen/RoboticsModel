# Импорт URDF и 3D-моделей

Импорт написан без сторонних библиотек: свой XML-парсер (`src/io/xml.{hpp,cpp}`), чтение STL/OBJ (`include/robotics/io/mesh.hpp`, `src/io/mesh.cpp`) и построение `World` через публичный API (`include/robotics/io/urdf.hpp`, `src/io/urdf.cpp`).

## Где это доступно

| Где | Как |
|---|---|
| Редактор | **File → Import URDF…** (⌘I), флажок «Fix the base to the ground»; **File → Open…** тоже принимает `.urdf` |
| Редактор | **File → Import 3D Model as Visual…** (⇧⌘I) для выбранной детали: «Fit to the part» / метры / миллиметры; **Remove 3D Model** |
| Редактор | **View → Show Collision Shapes** (⌥⌘C): формы столкновений полупрозрачно поверх моделей |
| Редактор | **Examples → Diff-Drive Robot / Mesh Arm / Two-Link Arm / Gripper (URDF)** |
| CLI | `robotics_cli --urdf path.urdf [--fix-base] [--seconds N] [--save out.robot]`; предупреждения — в stderr |
| C++ | `loadUrdf(path, options)` / `importUrdf(stream, options, sourcePath)` → `UrdfImportResult{world, robotName, warnings}` |

После импорта появляется окно с замечаниями (что приближено или пропущено). Ошибки разбора показываются с именем файла, строкой и столбцом, например `robot.urdf, line 9, column 13: closing tag </visual> does not match <collision> opened on line 5`.

## Опции (`UrdfImportOptions`)

| Поле | По умолчанию | Смысл |
|---|---|---|
| `fixBase` | false | Корневое звено (и всё, что приварено к нему `fixed`) получает массу 0 — статично |
| `zUpToYUp` | true | URDF — Z вверх, наш мир — Y вверх: робот поворачивается на −90° вокруг X, URDF (x, y, z) → мир (x, z, −y). Вперёд остаётся +X, «влево» (+Y URDF) становится −Z |
| `spawnOffset` | 0 | Смещение всего робота в мировых координатах после поворота |
| `liftAboveGround` | true | Поднять робота так, чтобы ни одна форма столкновений не начиналась ниже пола. Не действует, если основание закреплено (`fixBase` или корень `world`): тогда выдаётся предупреждение о деталях ниже пола |
| `defaultEffort` | 10 | `maxTorque` (Н·м или Н) для приводных соединений без `<limit effort>` |
| `minimumMass` | 0.01 | Масса звеньев без `<mass>` или с нулевой массой |
| `meshSearchPaths` | — | Дополнительные папки для мешей; также используется `ROS_PACKAGE_PATH` |
| `meshCollision` | `ConvexHull` | `<collision>` с мешем: `ConvexHull` — выпуклая оболочка меша, `BoundingBox` — охватывающая коробка |

Звено с именем `world` в корне считается неподвижной опорой, как при `fixBase`.

## Соответствие URDF → модель

| URDF | Модель |
|---|---|
| `revolute` | `Hinge`; `setLimits(lower, upper)` (рад); `maxTorque = effort` |
| `continuous` | `Hinge` без ограничений; `maxTorque = effort` или `defaultEffort` |
| `prismatic` | `Prismatic` (Slider); `setLimits` (м); `maxTorque = effort` (Н) |
| `fixed` | `Fixed` (между двумя статичными телами соединение не создаётся) |
| `floating`, `planar` | Пропускаются с предупреждением: дочернее звено — свободная деталь |
| `<origin xyz rpy>` | rpy — фиксированные оси: R = Rz(yaw)·Ry(pitch)·Rx(roll) |
| `<axis xyz>` | Ось соединения в системе дочернего звена (по умолчанию 1 0 0) |
| `<inertial><mass>` | `Body::mass`; инерция считается **по форме** тела |
| `<collision> box` | `Box`, `size` как есть |
| `<collision> sphere` | `Sphere`, диаметр = 2·radius |
| `<collision> cylinder` | `Cylinder` (ось — локальная Z, как в URDF): диаметр = 2·radius, `size.z = length` |
| `<collision> mesh` | `ConvexHull`: выпуклая оболочка меша с учётом `scale`, до 64 вершин (при упрощении предупреждение). Тело стоит в центре масс на главных осях, визуальные меши остаются на месте. Плоский меш (или тоньше 2 мм) — коробка + предупреждение. При `meshCollision = BoundingBox` — охватывающая коробка + предупреждение |
| `<visual> mesh` (STL/OBJ) | `Body::visuals` — рисуется вместо примитива; физика не меняется |
| `<visual> box/sphere/cylinder` | Не рисуется отдельно: рисуется примитив столкновений |
| `<limit velocity>`, `<dynamics>`, `<mimic>`, `<safety_controller>`, `<calibration>` | Не моделируются (`dynamics`, `mimic` — с предупреждением) |
| `<material>`, `<gazebo>`, `<transmission>` | Игнорируются |

Позы считаются обходом дерева в нулевой конфигурации: рамка звена = рамка родителя ∘ origin соединения; тело = рамка звена ∘ origin столкновения. Якорь соединения — начало рамки дочернего звена; `World::connect` принимает эту позу за ноль координаты, поэтому `Joint::angle` совпадает с координатой URDF.

### Звенья, которые не ложатся на «одно тело»

- **Несколько `<collision>`** — первое становится телом звена (имя звена), остальные — отдельными телами `<звено>_collision_N`, приваренными `Fixed`. Масса делится пропорционально объёму. Если у звена есть визуальный меш, примитивы дополнительных тел скрыты (`primitiveHidden`).
- **Нет `<collision>` и звено прикреплено `fixed`** (tool0, кронштейны датчиков) — сливается с телом родителя: масса добавляется, визуальные меши переносятся с правильной позой.
- **Нет `<collision>`, но звено подвижное** (или у корня есть подвижные дети, или есть видимый меш) — создаётся маленькая скрытая сфера-заглушка 4 см с массой звена. Она участвует в столкновениях — это компромисс, отмечен в предупреждениях.
- **Корень без геометрии только с `fixed`-детьми** (`base_footprint`) — чистая система отсчёта, тела нет; дети становятся свободными деталями.
- Если визуальный меш не найден или в неподдерживаемом формате (например `.dae`), а столкновение задано STL/OBJ — рисуется меш столкновений.

## Пути к мешам

- `package://pkg/path` (и `model://`): от папки URDF вверх ищется каталог с именем `pkg` или с `package.xml`, где `<name>pkg</name>` (или каталог, содержащий `pkg/`), затем `meshSearchPaths` и `ROS_PACKAGE_PATH` (как родитель пакета и как сам пакет).
- `file:///abs/path` и абсолютные пути — как есть; относительные — от папки URDF.
- Сцены с видимыми моделями пишутся в `.robot` версии 4 (её же требует нестандартное `World::iterations`, например у стартового rover — такие файлы не откроются старыми сборками). Подробности — ARCHITECTURE.md, «Формат `.robot`».
- В `.robot` пути внутри папки сцены сохраняются относительными, остальные — абсолютными; при загрузке относительные пути разрешаются от папки сцены.

## Форматы мешей

- **STL**: двоичный и ASCII определяются по содержимому (двоичный файл с заголовком `solid` тоже распознаётся по размеру). Нормали пересчитываются по вершинам.
- **OBJ**: `v`, `vn`, `f` (`v`, `v/vt`, `v//vn`, `v/vt/vn`, отрицательные индексы); многоугольники, в том числе невыпуклые, триангулируются отсечением ушей. `vt`, материалы, группы игнорируются (цвет детали задаёт редактор).
- Единицы не хранятся в файлах: URDF задаёт `scale`, в «Import 3D Model» есть выбор «метры / миллиметры / подогнать к детали».
- COLLADA (`.dae`), glTF, FBX не поддерживаются — конвертируйте в STL/OBJ.

## Реальные роботы

**UR5 (`ur_description`)**:
1. Получите URDF из xacro на машине с ROS: `xacro ur5.urdf.xacro > ur5.urdf` (xacro-файлы импортёр отклоняет с подсказкой).
2. Положите `ur5.urdf` внутрь папки пакета (например `ur_description/urdf/`) или передайте папку, содержащую `ur_description`, в `meshSearchPaths`/`ROS_PACKAGE_PATH`.
3. Визуальные меши UR — `.dae`: импортёр предупредит и нарисует STL-меши столкновений (`meshes/ur5/collision/*.stl`). Для точного вида сконвертируйте `.dae` в `.obj` (Blender/MeshLab) и поправьте пути.
4. Импортируйте с «Fix the base». Столкновения звеньев — охватывающие коробки, поэтому соседние несвязанные звенья могут касаться друг друга раньше, чем реальные.

**TurtleBot3 (`turtlebot3_description`)**: тоже xacro → URDF; меши STL читаются напрямую. `base_footprint` станет системой отсчёта, колёса — Hinge без ограничений, шарик-опора — сфера. WASD управляет колёсами (направление «вперёд» — +X корпуса).

## Ограничения и приближения

- Инерция: берётся только масса; тензор инерции и смещение центра масс (`<inertial><origin>`) не используются — инерция считается по форме тела.
- Меш-столкновения по умолчанию — выпуклая оболочка (до 64 вершин, quickhull + GJK/EPA); альтернатива — охватывающая коробка (`meshCollision = BoundingBox`). Невыпуклые меши заменяются выпуклой оболочкой.
- Замкнутые цепи, `mimic`, ограничение скорости, трение/демпфирование суставов, `floating`/`planar` не поддерживаются.
- Трение и упругость — значения по умолчанию (`<gazebo><mu1>` не читается).
- Тела-заглушки участвуют в столкновениях.
- Большие меши рисуются, но каждый кадр перестраиваются на CPU: сотни тысяч треугольников заметно замедлят вьюпорт.
