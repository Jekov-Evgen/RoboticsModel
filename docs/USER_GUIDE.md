# Robotics Model — руководство пользователя

Учебная среда конструирования и моделирования роботов в **3D на C++20**, с собственным физическим ядром. Bullet, PhysX, MuJoCo и другие готовые физические движки не используются.

Это работающий начальный прототип для курсового проекта: можно собрать конструкцию из деталей, соединить их суставами, задать моторы и запустить динамику. Архитектура описывает робота графом звеньев, а не заранее заданным классом «манипулятор». Буквально произвольные роботы пока не поддерживаются: доступные формы и соединения перечислены ниже.

## Запуск на macOS

Нужны Command Line Tools с `clang++` и `make`. Сторонние библиотеки не нужны.

```sh
make
make test
./build/robotics_editor
```

Откроется конструктор со **стартовым четырёхколёсным роботом** на площадке 80 × 80 м. Это обычная сборка из редактируемых тел и соединений: можно менять размеры, массы, положение, приводы, добавлять и удалять детали, сохранять собственную версию. Меню **Examples** на панели инструментов загружает стартовый ровер, манипулятор, PID-стенд, линейный привод с ограничениями (Linear Actuator & Limits) или пустую сцену; смену сцены можно отменить через ⌘Z.

Кликни по 3D-виду: **W/S** — вперёд/назад, **A/D** — разворот на месте, **X** — торможение. Команда действует до следующего нажатия; W/A/S/D также запускают физику, если она на паузе. **Space** — Run/Pause. **Reset** возвращает состояние перед первым запуском. После изменения конструкции создаётся новая точка сброса при следующем Run. Клавиши управления не работают при вводе текста в инспекторе — сначала верни фокус кликом в 3D-вид. **Help → Quick Start Guide** (⌘?) показывает краткую инструкцию.

`make` также собирает **build/RoboticsModel.app** с иконкой для Finder и Dock. Можно открыть приложение двойным щелчком или командой:

```sh
open build/RoboticsModel.app
```

Ядро, формат сцен и консольная программа написаны на переносимом C++20. Окно первой версии использует Cocoa и небольшой слой Objective-C++; графический редактор сейчас доступен **только на macOS**.

### CMake: ядро и консоль, включая другие ОС

```sh
cmake -S . -B build/cmake -DCMAKE_BUILD_TYPE=Release
cmake --build build/cmake --config Release
ctest --test-dir build/cmake -C Release --output-on-failure
```

На macOS дополнительно создаётся `robotics_editor.app`. На Linux/Windows собираются ядро, CLI и тесты. Перенос на эти ОС предусмотрен структурой проекта, но в текущем окружении проверена только сборка Apple Clang через Make.

## Что уже работает

- Трёхмерные положение, ориентация кватернионом, линейная и угловая скорость.
- Масса, диагональный тензор инерции в локальной системе, силы и моменты.
- Формы: ориентированная коробка, сфера и цилиндр (колесо); неподвижный пол `Y = 0`.
- Столкновения sphere–sphere, sphere–box, box–box и всех форм с полом.
- Нормальные импульсы, коэффициент восстановления и кулоновское трение.
- Соединения Fixed, Ball, Hinge и Slider (поступательный сустав, `Prismatic`); скоростной мотор с ограничением момента (Hinge) или силы (Slider).
- Ограничения хода Hinge (угол, в редакторе — градусы; диапазон может быть шире ±180°) и Slider (метры): жёсткие односторонние связи, которые держат и против мотора.
- Настраиваемые P, PI, PD, PID и Relay для положения или скорости Hinge и Slider; anti-windup и фильтр производной.
- Окно Control Lab с графиками отклика, ошибки и момента/P/I/D; настройка на ходу, экспорт CSV/PNG.
- Конструктор с выбором деталей, редактированием параметров, сборкой соединений и сохранением `.robot`.
- Перспективный 3D-вид с вращением камеры и приближением.
- Детерминированный шаг симуляции `1/240 с`, консольные прогоны и экспорт поз в CSV.

## Интерфейс редактора

Окно разделено на три части:

- **Parts** (слева) — дерево деталей: дочерние детали вложены в родителя, рядом указан тип соединения. Внизу кнопки **Box / Ball / Wheel** для добавления деталей. Правый клик — Duplicate / Delete.
- **3D-вид** (в центре) — сверху состояние симуляции и кнопки ракурсов (Perspective / Top / Front / Side), снизу подсказки по управлению. Сообщения и ошибки появляются всплывающими подсказками, без модальных окон.
- **Inspector** (справа) — свойства выбранной детали (*Selected part*), её соединение с родителем (*Connection to parent*) и блок *Drive & Control*.

На панели инструментов: Run/Pause, Reset, Undo/Redo, Add, Delete, Examples (Rover, Arm, PID Test Bench, Empty Scene), Open, Save, Control Lab, Help. **Каждое изменение отменяется через ⌘Z** (повтор — ⇧⌘Z). При закрытии с несохранёнными изменениями приложение предложит сохранить сборку.

## Перемещение, запись, графики и библиотека

**Гизмо.** Клавиши **1 / 2 / 3** (или кнопки Select / Move / Rotate в 3D-виде) выбирают инструмент. На паузе у выбранной детали появляются стрелки X/Y/Z и квадраты плоскостей (Move) или три кольца (Rotate); размер на экране постоянен. Деталь перемещается и вращается вместе со всем, что прикреплено ниже, соединения остаются целыми; одно перетаскивание — один шаг Undo. Рядом с кнопками — шаг привязки: сетка 1/5/10/25 см и угол 5/15/45°. **⌘** во время перетаскивания инвертирует привязку. **Drop** ставит сборку на пол (y = 0).

**Запись.** Каждый запуск записывается (60 кадров/с, последние 60 с; длина — в меню «…» таймлайна). Таймлайн внизу 3D-вида: перетаскивание ползунка ставит симуляцию на паузу и показывает кадр, не меняя её состояние; **← →** — шаг на кадр, Play со скоростью 0.25×–4×, **Esc / Live** — вернуться к текущему состоянию, **Resume Here** — продолжить симуляцию с показанного кадра (более поздние кадры удаляются). Там же экспорт всей записи в CSV. Любое изменение конструкции очищает запись.

**Plots (⌘P).** Окно с поиском по всем величинам: положение, скорости, углы, энергия деталей и сцены, координаты, усилия и реакции соединений, число контактов, каналы датчиков. Величины с одной единицей попадают на один график, New Chart создаёт отдельный. Наведение показывает значения под курсором, при просмотре записи линия следует за таймлайном, щелчок по графику перематывает запись. Pause замораживает графики, Export CSV сохраняет выбранные величины. Правый щелчок по детали в 3D, в списке Parts или по полям инспектора — быстрые команды Plot Position, Plot Speed и другие.

**Library (⌘B).** Готовые модули: ведущее колесо, сервопривод, линейный привод, двухпальцевый захват, шаровая опора, плита шасси, мачты с лидаром и камерой, плата IMU. С выбранной деталью модуль крепится к ней в свободном месте (колесо — горизонтальным шарниром сбоку), иначе ставится на пол. Имена становятся уникальными, вставка отменяется одним ⌘Z. **Save Selected Assembly** сохраняет выбранную деталь с прикреплёнными как файл `.robot` в `~/Library/Application Support/RoboticsModel/Library`; также читается папка `Library` рядом с открытым файлом робота.

## Как собрать робота

1. **Examples → Empty Scene** (⌘N), затем **Add → Box** (⌘1). В Inspector задай имя, положение и размер. Отметь **Fixed in place**, чтобы закрепить деталь как основание.
2. Добавь следующую деталь: **Box / Ball / Wheel** (⌘1/⌘2/⌘3). Поля применяются сразу по Return или при уходе из поля; неверное число подсвечивается красным, и модель не меняется. Для шара задаётся диаметр, для колеса — диаметр и ширина (ось колеса — локальная Z).
3. В блоке **Connection to parent** выбери родителя в **Attach to**, тип **Fixed / Ball / Hinge / Slider**, точку крепления (**Midpoint** ставит её посередине между деталями) и ось (быстрые кнопки X/Y/Z). Нажми **Create connection**. Для колеса анкер и ось подставляются автоматически по его оси.
4. Для Hinge задай скорость мотора (рад/с) и максимальный момент (Н·м), для Slider — скорость (м/с) и максимальную силу (Н); при нуле мотор выключен. Галочка **Limit range** с полями **Min / Max** ограничивает ход (Hinge — градусы, Slider — метры, отсчёт от позы при создании соединения).
5. **Run** (Space) запускает физику, **Reset** (⇧⌘R) возвращает исходные позы. Во время симуляции Inspector заблокирован: для правки нажми Pause.
6. **Save** (⌘S) сохраняет в текущий файл, **Save As…** (⇧⌘S) — в новый файл, **Open…** (⌘O) загружает `.robot`.

**Перемещение деталей:** удерживай **Option** и тащи деталь в 3D-виде по горизонтали; с **Option+Shift** — вверх/вниз. Перемещение детали (и через поле Position) переносит вместе с ней всё, что к ней прикреплено: например, сдвиг шасси двигает весь ровер, а соединения не разрываются. При повороте через Rotation соединения сохраняют свои мировые точки крепления.

**Камера:** перетаскивание — орбита; Shift + перетаскивание или правая кнопка — панорама; колесо или щипок на трекпаде — зум; клик — выбор детали, клик по пустому месту снимает выбор; `F` или ⌘0 — вернуть камеру к роботу; ⌥⌘1…4 — ракурсы. Площадка — 80 × 80 м с метровой сеткой; физический пол бесконечный.

**Приводы колёс:** четыре Hinge с моментом до 8 Н·м. WASD задаёт скорости цилиндрическим звеньям в режиме Speed motor; левую/правую сторону определяет знак Z точки крепления в системе родителя. Предполагаются параллельные оси +Z, как в стартовой сборке. После произвольного изменения осей/топологии направление команд может потребовать настройки приводов. Колёса под P/PI/PD/PID/Relay клавиатура не перенастраивает — они управляются через Control Lab. Переименование не влияет на управление; специальные цвета исходных декоративных деталей привязаны к их именам.

**Единицы:** метры, килограммы, секунды, ньютоны. `Y` направлена вверх. В инспекторе углы Эйлера заданы в градусах, порядок поворотов — `Rz * Ry * Rx`; моторы используют рад/с. Ось нормализуется автоматически. Детали массой 0 неподвижны. Начальные глубокие пересечения деталей лучше не создавать.

## Примеры и эксперименты

**Регуляторы:** нажми **Control Lab** на панели инструментов (⌘L), затем **Load PID step-response demo** и **Run / Pause**. Меняй параметры и нажимай Apply; Reset повторяет опыт с новыми коэффициентами. Подробности, единицы и формулы — в [docs/CONTROLLERS.md](CONTROLLERS.md).

Готовые сцены находятся в `examples/`: одношарнирный маятник, пространственный манипулятор с непараллельными осями, PID-сервопривод и `linear_actuator.robot` (каретка на Slider с PID и ограничениями плюс заслонка на Hinge с ограничением угла). Их можно открыть в редакторе.

```sh
# Встроенный манипулятор, 10 секунд физического времени
./build/robotics_cli --seconds 10

# Колёсная платформа, прямолинейное движение
./build/robotics_cli --rover-demo --seconds 5 --csv build/rover.csv

# Пространственный манипулятор, экспорт поз каждые 4 шага (60 Гц)
./build/robotics_cli --scene examples/spatial_arm.robot --seconds 5 --csv build/poses.csv

# Сохранить исходный встроенный пример, не запуская динамику
./build/robotics_cli --seconds 0 --save build/demo.robot

# Переходный процесс PID; полный журнал управления на 240 Гц
./build/robotics_cli --control-demo --seconds 10 --control-csv build/pid-response.csv

# Автопроверка редактора на macOS; на мгновение открывает окно,
# сохраняет build/editor-preview.png и завершает приложение
./build/robotics_editor --smoke-test
```

## Импорт URDF и 3D-моделей

**File → Import URDF…** (⌘I) загружает робота из `.urdf` (флажок «Fix the base» делает основание неподвижным — для манипуляторов). Звенья становятся деталями, `revolute`/`continuous` — Hinge, `prismatic` — Slider, `fixed` — Fixed; пределы и `effort` переносятся. Меши ищутся рядом с файлом и в папках пакетов (`package://имя/...` — поиск вверх по каталогам). Видимая геометрия: STL (двоичный и ASCII) и OBJ; столкновения по мешу — выпуклая оболочка (до 64 вершин). Всё, что пришлось упростить, перечисляется в окне предупреждений. **File → Import 3D Model as Visual…** (⇧⌘I) показывает STL/OBJ вместо формы выбранной детали (физика не меняется); **View → Show Collision Shapes** (⌥⌘C) показывает формы столкновений поверх моделей. Примеры: меню **Examples → … (URDF)** и папка `examples/urdf/`.

```sh
./build/robotics_cli --urdf examples/urdf/diff_drive.urdf --seconds 5
./build/robotics_cli --urdf examples/urdf/demo_meshes/urdf/mesh_arm.urdf --fix-base
```

Таблица соответствия, ограничения и как подключить реальный робот (UR5, TurtleBot3) — в [docs/IMPORT.md](IMPORT.md).

CLI округляет длительность до ближайшего целого числа шагов. CSV содержит `time, body_id, x, y, z, qw, qx, qy, qz`. При длительности, не кратной 1/60 с, последняя строка экспорта может предшествовать конечному шагу. CLI выводит максимальную ошибку креплений за весь прогон; это один диагностический показатель, не доказательство точности всей физики.

## Структура

```text
include/robotics/          Публичный API ядра (без UI): math, body, joint, contact,
                           controller, world, demo_scenes; io/robot_format.hpp — формат .robot;
                           scene.hpp — заголовок совместимости; robotics.hpp — всё ядро сразу
src/physics/               Физика: шаг мира, тела, столкновения, решатели контактов и
                           соединений, энкодеры и приводы
src/control/               Регуляторы P/PI/PD/PID/Relay, сигналы задания, CSV
src/io/                    Сцены .robot, импорт URDF, собственный XML-парсер, чтение STL/OBJ
src/scenes/                Встроенные примеры: манипулятор, PID-стенд, колёсная платформа
src/editing/               Правки сборок (перенос, поворот, на пол), математика гизмо, библиотека деталей
src/replay/                Запись симуляции (кольцевой буфер, восстановление), каналы графиков
src/cli/main.cpp           Консольный запуск и экспорт измерений
src/mac/                   Нативный конструктор macOS: окно и состояние (editor_controller),
                           инспектор, меню, дерево деталей, документы, Control Lab,
                           GPU-рендер Metal (viewport), автопроверка --smoke-test
tests/                     Тесты по областям (test_*.cpp) и общий каркас test_harness.hpp
tools/icon_builder.mm      Сборка иконки приложения
examples/                  Готовые конструкции
docs/ARCHITECTURE.md       Архитектура, карта модулей, правила зависимостей, соглашения,
                           как добавить тип соединения, импортёр или тест
docs/CONTROLLERS.md        Регуляторы, графики и настройка экспериментов
docs/IMPORT.md             Импорт URDF и 3D-моделей: соответствие, ограничения, реальные роботы
```

Правила: ядро (`include/robotics`, `src/physics|control|io|scenes|sensors|editing|replay`) зависит только от стандартной библиотеки C++20; `src/mac` и `src/cli` зависят от ядра, но не наоборот. Код форматируется `make format` по `.clang-format`.

## Границы прототипа

Физика трёхмерная, но пока это **учебный rigid-body симулятор**, а не замена промышленной среды робототехники. Нет деформации шин, столкновений по невыпуклой форме сеток (меш столкновений заменяется выпуклой оболочкой), трения и демпфирования в суставах, мягких тел и моделирования жидкостей. По умолчанию контроллеры используют идеальные измерения положения и скорости сустава; шум, квантование и задержку энкодера включают через модель датчика (см. [SENSORS.md](SENSORS.md)).

Колёса имеют цилиндрическую инерцию и аналитический контакт с землёй без гранёного качения. Sphere–cylinder также учитывает круглую форму; cylinder–box и cylinder–cylinder пока используют охватывающие ориентированные коробки и могут давать ранние контакты возле углов. Это базовая модель жёсткого колеса с сухим трением, без подвески и деформации резины.

Контакты строятся методом SAT с манифольдом до 4 точек, выпуклые оболочки — через GJK/EPA. Быстрые тела останавливаются на тонких препятствиях непрерывным обнаружением столкновений (`World::continuousCollision`, `Body::ccd`). Гироскопический член учитывается. Sleeping (засыпание тел) не реализован. Соседние звенья, связанные любым соединением, не сталкиваются друг с другом.

Отрисовка выполняется на GPU через **Metal** (`src/mac/viewport.mm`): reversed-Z буфер глубины, 4× MSAA, освещение по нормалям и плоские тени со stencil-буфером. Поэтому детали корректно перекрывают друг друга и не просвечивают. Шейдеры компилируются при запуске, отдельный Metal toolchain не нужен. Сквозь детали слегка видны только оранжевые маркеры шарниров. Рендерер пока только для macOS; переносимый вариант (OpenGL/Vulkan + ImGui) остаётся в планах.

Подробный план развития и материал для пояснительной записки — в [docs/ARCHITECTURE.md](ARCHITECTURE.md).
