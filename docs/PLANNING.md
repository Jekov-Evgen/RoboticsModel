# Кинематика и планирование траекторий

Модуль `include/robotics/kinematics/` (ядро, C++20) и его Python-обёртка работают с **любой последовательной цепочкой суставов** из `World`: манипулятор из примера, импортированный URDF, собранная в редакторе рука.

```python
import numpy as np, robotics_model as rm

world = rm.load_scene("examples/manipulator_3dof.robot")
chain = world.make_chain("tool")                 # от базы до тела "tool"; tip_point=(x, y, z) — точка в его системе
chain.dofs, chain.joints, chain.actuated         # 3, [0, 1, 2, 3], [0, 1, 2] (сварка инструмента — без координаты)
```

## Прямая кинематика и якобиан

`chain.forward(q)` возвращает положение и кватернион контролируемой точки для углов `q`, а `chain.jacobian(q)` — геометрический якобиан 6 × n (линейная скорость точки и угловая скорость инструмента на единичную скорость сустава, в мировых осях).

Конвенции движка: координата Hinge — поворот B вокруг `axisA` относительно позы в момент `connect()`; Prismatic — смещение якоря B вдоль `axisA`; Fixed входит в цепочку без координаты; Ball не поддерживается. Геометрия берётся из `World` в момент вызова, поэтому кинематика следует за правками робота. Ошибка прямой кинематики относительно реального положения симулируемого инструмента — меньше 0,2 мм (она ограничена лишь дрейфом связей).

## Обратная кинематика

`chain.solve_ik(target_position, target_orientation=None, seed=None, ...)` — метод демпфированных наименьших квадратов (Levenberg–Marquardt): `dq = Jᵀ(J Jᵀ + λ²I)⁻¹e`, ограничение шага, зажим по пределам хода суставов (`respect_limits`). Цель по положению (3 уравнения) либо по полной позе (6). Результат всегда содержит лучшие найденные углы, но признак успеха — `result.converged`: недостижимая цель или упор в предел честно возвращает `False` вместо подгонки.

Что проверено тестами (`tests/test_kinematics.cpp`): якобиан совпадает с конечными разностями; для трёхосевой руки решается не менее 95 % случайных достижимых целей (на практике все), для шестиосевой — цели по полной позе; предел хода блокирует цель; цель за пределами досягаемости не решается.

Ограничения метода: ищется одно решение рядом с начальным приближением (`seed`), без перебора ветвей «локоть вверх/вниз»; вблизи сингулярностей (рука вытянута в линию) демпфирование жертвует точностью ради устойчивости.

## Траектории

Все траектории — это `Trajectory`: массивы положения, скорости и ускорения с постоянным периодом (по умолчанию 2 мс); `sample(t)` интерполирует.

| Функция | Что делает |
|---|---|
| `plan_point_to_point(start, goal, max_velocity, max_acceleration)` | профиль **minimum-jerk** из покоя в покой; длительность — минимальная, при которой соблюдены пределы: пик скорости `15/8·Δq/T`, пик ускорения `10/√3·Δq/T²` |
| `plan_waypoints(waypoints, ...)` | последовательность таких отрезков с остановкой в каждой точке |
| `chain.plan_line(q_start, target, ...)` | **прямая в пространстве** для контролируемой точки: ОЗК в 100 точках вдоль линии, время подбирается так, чтобы выдерживались пределы скорости и ускорения по суставам. Возвращает `None`, если ОЗК не решается где-то на линии |

Пределы можно задать числом (для всех суставов) или по значению на сустав. Тесты проверяют начало и конец в покое, соблюдение пределов, согласованность скорости с производной положения, прямолинейность плана (в пределах 2 мм) и отказ при недостижимой цели.

**Сингулярность.** Если начать линию из полностью вытянутой руки (локоть 0°), длительность вырастет в разы: чтобы двигать инструмент внутрь, локтю нужна почти бесконечная скорость, и пределы это честно учитывают. Стартуйте из согнутой позы.

## Исполнение в симуляции

`rm.follow_trajectory(world, chain, trajectory, settle=0.5)` задаёт уставки PID-регуляторов суставов по траектории и шагает мир. Важно понимать, что происходит дальше: у регуляторов **нет ни гравитационного, ни скоростного feedforward**, поэтому исполненное движение отстаёт от плана и «проседает», причём тем сильнее, чем быстрее траектория. Измерено на манипуляторе из примера (прямая 0,46 м в пространстве, макс. отклонение инструмента от линии / ошибка в конце):

| пределы (скорость, ускорение) | длительность | макс. отклонение от прямой | ошибка в конце |
|---|---:|---:|---:|
| 2,0 рад/с, 8 рад/с² | 1,7 с | 68 мм | 7,2 мм |
| 1,0 рад/с, 4 рад/с² | 2,3 с | 54 мм | 4,2 мм |
| 0,5 рад/с, 2 рад/с² | 3,9 с | 31 мм | 1,7 мм |
| 0,3 рад/с, 1 рад/с² | 6,5 с | 15 мм | 0,7 мм |
| 0,15 рад/с, 0,5 рад/с² | 13,1 с | 5 мм | 0,1 мм |

Это не ошибка планировщика: сам план прямой с точностью до 2 мм. Если нужна точность следования на скорости, понадобится feedforward в регуляторах (в планах), пока — планируйте медленнее.

## Чего здесь нет

- Планирования с обходом препятствий (RRT и т. п.): цепочка сталкивается с миром только физически, при исполнении.
- Ограничения по ориентации вдоль линии (`plan_line` ведёт одну точку).
- Кинематики замкнутых цепей и шаровых суставов.
